# Специфікація REST API StudyPlanner

Цей документ містить повний опис REST API застосунку **StudyPlanner**: протоколи взаємодії, кінцеві точки, схеми запитів та відповідей, правила валідації та коди помилок.

---

## 1. Загальні конвенції та правила

- **Базовий шлях (Base URL):** `/api`
- **Формат обміну даними:** `application/json` із кодуванням UTF-8.
- **Автентифікація:** Здійснюється через сесійний cookie `sp_session` (`HttpOnly; SameSite=Lax; Path=/`). Значення cookie має вигляд `<uuid>.<HMAC-SHA256>` і перевіряється на сервері; підроблене або пошкоджене значення відхиляється зі статусом `401`. Прапорець `Secure` вмикається у production (керується змінною `COOKIE_SECURE`). Заголовок `Authorization: Bearer ...` не використовується.
- **Ізоляція даних (Multi-tenancy):** Усі маршрути завдань та дисциплін суворо обмежені обліковим записом поточного автентифікованого користувача. Спроба доступу до чужого ресурсу за ID повертає статус `404 Not Found`. Некоректний (не-UUID) `:id` також повертає `404`, щоб не відрізняти «не існує» від «не може існувати».
- **Робота з датами:** Поле дедлайну (`deadline`) зберігається як календарна дата без часового поясу (`DATE` у PostgreSQL) і передається у форматі рядка `"YYYY-MM-DD"`. Поля міток часу (`completedAt`, `createdAt`, `updatedAt`) передаються у стандарті ISO 8601 (UTC). Неіснуючі дати (наприклад, `2027-02-31`) відхиляються зі статусом `422`.
- **Ідентифікатори:** Усі `id` сутностей є криптографічно стійкими унікальними рядками у форматі UUIDv4 (наприклад, `"c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7"`).
- **Сувора валідація:** Будь-які непередбачені поля у тілі запитів (POST/PATCH) автоматично відхиляються сервером зі статусом `422 Unprocessable Entity` (захист від Mass Assignment).
- **Обмеження розміру тіла:** Максимальний розмір JSON-тіла запиту — **16 КБ**; більші запити відхиляються зі статусом `413`.
- **Обмеження частоти запитів:** `POST /api/auth/register`, `/api/auth/login`, `/api/account/delete` і `/api/account/password` мають auth-ліміт 10 запитів на хвилину з однієї IP-адреси; захищені маршрути акаунта також залишаються в межах загального API-ліміту. Решта маршрутів `/api/*` має загальний ліміт 100 запитів на хвилину. У відповіді `429` повертаються заголовки `Retry-After` та `RateLimit-*`.

## 2. Стандартизований формат помилок

Усі помилкові відповіді сервера мають уніфіковану JSON-структуру:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Введені дані некоректні",
    "fields": {
      "title": "Введіть назву від 3 до 100 символів",
      "deadline": "Вкажіть коректний дедлайн"
    }
  }
}
```

### Основні коди помилок (Error Codes)
| Код помилки | HTTP Статус | Опис ситуації |
|---|:---:|---|
| `BAD_REQUEST` | 400 | Невалідний JSON у тілі запиту або некоректний формат ідентифікатора |
| `BAD_CONTENT_TYPE` | 400 | Для зміни стану не передано `Content-Type: application/json` |
| `BAD_ORIGIN` | 400 | Невалідний заголовок `Origin` |
| `AUTH_REQUIRED` | 401 | Сесійний cookie відсутній |
| `SESSION_EXPIRED` | 401 | Сесія недійсна, підроблена або прострочена |
| `INVALID_CREDENTIALS` | 401 | Невірна пошта або пароль |
| `INVALID_CURRENT_PASSWORD` | 403 | Поточний пароль не підтверджено |
| `CSRF_FORBIDDEN` | 403 | Міждоменний (`Origin` ≠ `Host`) запит на зміну стану |
| `NOT_FOUND` | 404 | Ресурс не існує, належить іншому користувачеві або `:id` не є UUID |
| `EMAIL_CONFLICT` | 409 | Користувач із такою електронною поштою вже зареєстрований |
| `DISCIPLINE_CONFLICT` | 409 | Дисципліна з такою назвою вже існує в користувача |
| `DISCIPLINE_HAS_TASKS` | 409 | Дисципліну не можна видалити, бо з нею пов'язані завдання |
| `CONFLICT` | 409 | Інше порушення унікальності або цілісності даних (fallback) |
| `PAYLOAD_TOO_LARGE`| 413 | Розмір тіла запиту перевищує 16 КБ |
| `VALIDATION_ERROR` | 422 | Помилка валідації значень полів або некоректне значення дати |
| `RATE_LIMIT` | 429 | Перевищено ліміт кількості запитів за одиницю часу |
| `INTERNAL_ERROR` | 500 | Непередбачена внутрішня помилка сервера |

## 4. Специфікація автентифікації

### 4.1. Реєстрація нового користувача
- **Маршрут:** `POST /api/auth/register`
- **Автентифікація:** Не потрібна.
- **Тіло запиту (Request Body):**
  ```json
  {
    "name": "Олександр Шевченко",
    "email": "student@lpnu.ua",
    "password": "Password123!",
    "acceptedTerms": true
  }
  ```
- **Правила валідації:**
  - `name`: рядок, обов'язковий, довжина від 2 до 100 символів (після trim).
  - `email`: рядок, обов'язковий, валідна адреса ел. пошти, до 255 символів.
  - `password`: рядок, обов'язковий, довжина від 8 до 128 символів.
  - `acceptedTerms`: обов'язкове логічне значення, має бути `true`; інакше повертається `422 VALIDATION_ERROR` з помилкою поля `acceptedTerms`.
- **Успішна відповідь (`201 Created`):**
  - Заголовок: `Set-Cookie: sp_session=<uuid>.<HMAC-SHA256>; HttpOnly; SameSite=Lax; Path=/`
  ```json
  {
    "user": {
      "id": "c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7",
      "name": "Олександр Шевченко",
      "email": "student@lpnu.ua"
    }
  }
  ```
- **Помилки:**
  - `409 Conflict`: email вже зайнятий (`"Користувач із такою електронною поштою вже зареєстрований"`).
  - `422 Unprocessable Entity`: порушення правил довжини або формату полів.

### 4.2. Вхід користувача
- **Маршрут:** `POST /api/auth/login`
- **Автентифікація:** Не потрібна.
- **Обмеження частоти:** Максимум 10 запитів на хвилину.
- **Тіло запиту (Request Body):**
  ```json
  {
    "email": "student@lpnu.ua",
    "password": "Password123!"
  }
  ```
- **Успішна відповідь (`200 OK`):**
  - Заголовок: `Set-Cookie: sp_session=<new-uuid>.<HMAC-SHA256>; HttpOnly; SameSite=Lax; Path=/`
  ```json
  {
    "user": {
      "id": "c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7",
      "name": "Олександр Шевченко",
      "email": "student@lpnu.ua"
    }
  }
  ```
- **Помилки:**
  - `401 Unauthorized`: невірний логін або пароль (`"Невірна пошта або пароль."`).
  - `429 Too Many Requests`: забагато спроб (`"Забагато спроб. Спробуйте пізніше."`).

### 4.3. Вихід користувача
- **Маршрут:** `POST /api/auth/logout`
- **Автентифікація:** Потрібна активна сесія.
- **Тіло запиту:** Відсутнє.
- **Успішна відповідь (`204 No Content`):**
  - Заголовок: `Set-Cookie: sp_session=; Max-Age=0; HttpOnly; SameSite=Lax; Path=/`
  - Тіло відсутнє.

### 4.4. Отримання даних поточного користувача
- **Маршрут:** `GET /api/auth/me`
- **Автентифікація:** Потрібна.
- **Успішна відповідь (`200 OK`):**
  ```json
  {
    "user": {
      "id": "c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7",
      "name": "Олександр Шевченко",
      "email": "student@lpnu.ua"
    }
  }
  ```
- **Помилки:**
  - `401 Unauthorized`: сесія відсутня, недійсна або прострочена.

## 5. Специфікація завдань (Tasks API)

### 5.1. Отримання списку завдань із фільтрацією
- **Маршрут:** `GET /api/tasks`
- **Параметри запиту (Query Parameters):**
  - `q` (string, опціонально): пошук підрядка у `title` та `description` (нечутливий до регістру).
  - `discipline` (UUID, опціонально): фільтр за ID дисципліни.
  - `done` (boolean: `"true"` або `"false"`, опціонально): фільтр за станом виконання.
  - `from` (string YYYY-MM-DD, опціонально): початкова дата дедлайну (включно).
  - `to` (string YYYY-MM-DD, опціонально): кінцева дата дедлайну (включно).
- **Успішна відповідь (`200 OK`):**
  ```json
  {
    "tasks": [
      {
        "id": "7b8e1f5d-4f2a-4c9b-8e1a-3a5c7d9e1f2b",
        "userId": "c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7",
        "disciplineId": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
        "discipline": {
          "id": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
          "name": "Web-дизайн",
          "colorIndex": 2
        },
        "title": "Здати лабораторну роботу №5",
        "description": "Підготувати звіт, скріншоти та виконати розгортання",
        "deadline": "2026-10-15",
        "done": false,
        "completedAt": null,
        "createdAt": "2026-10-06T10:00:00.000Z",
        "updatedAt": "2026-10-06T10:00:00.000Z"
      }
    ]
  }
  ```

### 5.2. Створення нового завдання
- **Маршрут:** `POST /api/tasks`
- **Автентифікація:** Потрібна.
- **Тіло запиту (Request Body):**
  ```json
  {
    "title": "Підготувати презентацію",
    "description": "Слайди про безпеку та доступність",
    "disciplineId": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
    "deadline": "2026-10-20"
  }
  ```
- **Правила валідації:**
  - `title`: обов'язковий рядок від 3 до 100 символів (після trim).
  - `description`: опціональний рядок, максимум 500 символів.
  - `disciplineId`: обов'язковий UUID, що належить поточному користувачеві.
  - `deadline`: обов'язковий рядок у форматі `YYYY-MM-DD`, реальна календарна дата.
- **Успішна відповідь (`201 Created`):**
  ```json
  {
    "task": {
      "id": "8f9a1b2c-3d4e-5f6a-7b8c-9d0e1f2a3b4c",
      "userId": "c4a8f9a2-9b21-4f1e-9d2a-14d2a938c5f7",
      "disciplineId": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
      "discipline": {
        "id": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
        "name": "Web-дизайн",
        "colorIndex": 2
      },
      "title": "Підготувати презентацію",
      "description": "Слайди про безпеку та доступність",
      "deadline": "2026-10-20",
      "done": false,
      "completedAt": null,
      "createdAt": "2026-10-06T12:00:00.000Z",
      "updatedAt": "2026-10-06T12:00:00.000Z"
    }
  }
  ```
- **Помилки:**
  - `404 Not Found`: дисципліна з таким `disciplineId` не існує або належить іншому користувачеві (`"Дисципліну не знайдено."`).
  - `422 Unprocessable Entity`: передано сторонні поля, помилка довжини полів або невалідна дата.

### 5.3. Отримання деталей завдання
- **Маршрут:** `GET /api/tasks/:id`
- **Автентифікація:** Потрібна.
- **Успішна відповідь (`200 OK`):**
  Повертає об'єкт завдання `{ task: {...} }`.
- **Помилки:**
  - `404 Not Found`: завдання не існує або належить іншому користувачеві.

### 5.4. Оновлення завдання / зміна стану виконання
- **Маршрут:** `PATCH /api/tasks/:id`
- **Автентифікація:** Потрібна.
- **Тіло запиту (можливе часткове передавання полів):**
  ```json
  {
    "done": true
  }
  ```
  або:
  ```json
  {
    "title": "Оновлена назва завдання",
    "deadline": "2026-10-25"
  }
  ```
- **Поведінка при зміні `done`:**
  - Якщо `done: true` -> `completed_at` автоматично встановлюється у поточний час `NOW()`.
  - Якщо `done: false` -> `completed_at` скидається у `null`.
- **Успішна відповідь (`200 OK`):**
  Повертає оновлений об'єкт завдання `{ task: {...} }`.
- **Помилки:**
  - `404 Not Found`: завдання не належить поточному користувачеві.
  - `422 Unprocessable Entity`: невалідні значення переданих полів.

### 5.5. Видалення завдання
- **Маршрут:** `DELETE /api/tasks/:id`
- **Автентифікація:** Потрібна.
- **Успішна відповідь (`204 No Content`):** Тіло порожнє.
- **Помилки:**
  - `404 Not Found`: завдання не знайдено або вже видалено.

  - `404 Not Found`: дисципліна не існує або належить іншому користувачеві.
  - `409 Conflict`: дисципліна прив'язана хоча б до одного завдання (`"Неможливо видалити дисципліну — є прив'язані завдання."`).

## 7. Специфікація акаунта (Account API)

Користувач керує зміною пароля й видаленням акаунта в захищених налаштуваннях акаунта (`account.html`). Контракти ендпоінтів нижче не залежать від розташування цієї сторінки.

### 7.1. Повне видалення облікового запису та даних
- **Маршрут:** `POST /api/account/delete`
- **Автентифікація:** Потрібна.
- **Тіло запиту:** `{ "password": "поточний пароль" }`.
- **Перевірка:** пароль перевіряється Argon2id; неправильне значення повертає `403 INVALID_CURRENT_PASSWORD`, не завершуючи сесію.
- **Поведінка:**
  - Видаляє запис користувача з таблиці `users`.
  - Завдяки `ON DELETE CASCADE` у базі даних безповоротно видаляються всі сесії, дисципліни та завдання цього користувача.
  - Очищує сесійний cookie `sp_session`.
- **Обмеження частоти:** використовує ліміт auth-маршрутів.
- **Успішна відповідь (`204 No Content`):** Тіло порожнє.
- **Помилки:**
  - `401 Unauthorized`: якщо користувач не авторизований.
  - `403 Forbidden`: поточний пароль неправильний.
  - `422 Unprocessable Entity`: відсутнє або некоректне поле пароля.

### 7.2. Зміна пароля
- **Маршрут:** `POST /api/account/password`
- **Автентифікація:** Потрібна.
- **Тіло запиту:** `{ "currentPassword": "поточний пароль", "newPassword": "новий пароль" }`.
- **Перевірка:** `currentPassword` перевіряється Argon2id; `newPassword` має бути від 8 до 128 символів і відрізнятися від поточного.
- **Поведінка:** зберігає новий хеш Argon2id, інвалідує всі інші сесії користувача й залишає поточну сесію активною.
- **Обмеження частоти:** використовує ліміт auth-маршрутів.
- **Успішна відповідь (`204 No Content`):** Тіло порожнє.
- **Помилки:** `401` без сесії, `403 INVALID_CURRENT_PASSWORD` при невірному поточному паролі, `422 VALIDATION_ERROR` при некоректному чи слабкому новому паролі.

## 8. Службові маршрути (System / Health API)

### 8.1. Перевірка працездатності системи
- **Маршрут:** `GET /api/health`
- **Автентифікація:** Не потрібна.
- **Призначення:** Використовується платформами розгортання (Render Health Check) та зовнішніми сервісами моніторингу працездатності.
- **Успішна відповідь (`200 OK`):**
  ```json
  {
    "status": "ok",
    "db": "ok",
    "uptime": 1420,
    "timestamp": "2026-11-04T12:00:00.000Z"
  }
  ```
- **Відповідь при збої бази даних (`503 Service Unavailable`):**
  ```json
  {
    "status": "degraded",
    "db": "error",
    "uptime": 1420,
    "timestamp": "2026-11-04T12:00:00.000Z"
  }
  ```

**Дата завершення:** 14.11.2026

**Гілка:** `main`

**Обсяг:** Neon Free, Render Free Web Service, production environment variables, міграції PostgreSQL і перевірка живого застосунку.

## 1. Підсумок

Фазу 4 завершено: перевірений застосунок розгорнуто на Render Free, PostgreSQL працює в Neon Free, міграції застосовані, користувач підтвердив роботу застосунку. Публічна адреса: [https://studyplanner-ec5s.onrender.com](https://studyplanner-ec5s.onrender.com).

Розгортання використовує merge-коміт `ce36e50` у `main`. Для нього GitHub Actions пройшов на закріпленому Node.js 22.23.5: [CI run 43580734789](https://github.com/Darkc0de-nvm/studyplanner/actions/runs/43580734789). Render успішно зібрав застосунок командою `npm ci --prefix server` і запустив його командою `npm start --prefix server`.

Ключові результати:

- Neon Free project `rough-sun-05511851` створено в регіоні AWS Europe (London); секретні connection strings зберігаються локально в кореневому `.env.local`, який ігнорується Git;
- Render Free Web Service створено з гілки `main`, Node.js 22.23.5 і кореневим каталогом репозиторію;
- перевірка `GET /api/health` на розгорнутому сервісі повернула `status: "ok"` і `db: "ok"`;
- у Neon успішно застосовано всі 6 SQL-міграцій (`001`–`006`); seed-дані не запускалися;
- користувач підтвердив, що розгорнутий застосунок працює.

## 2. Виконані кроки

1. Створено окремий Neon Free project для навчального деплою.
2. Створено Render Free Web Service з репозиторію `Darkc0de-nvm/studyplanner`, гілка `main`.
3. У Render задано production environment variables для Node, підключення до Neon, TLS та secure cookies. Секрети не зберігаються в репозиторії.
4. Застосовано шість міграцій до production-бази через локальний процес із direct/unpooled connection string.
5. Перевірено живий API health endpoint і роботу застосунку.

## 4. Експлуатаційні обмеження

- Render Free автоматично засинає після періоду без трафіку; перший запит після простою має холодний старт. Neon Free окремо зупиняє compute після неактивності.
- Не налаштовувати періодичний зовнішній запит до `/api/health`: маршрут виконує `SELECT 1`, тож такий моніторинг регулярно будитиме Neon. У Render залишити стандартну TCP-перевірку.
- Дані застосунку зберігаються в Neon, не у файловій системі Render. Seed не запускався.
- Цей деплой призначений для навчальної демонстрації, без production SLA. Поточні квоти та кроки відновлення описані у [`../deployment.md`](../deployment.md).
- URL застосунку потрібно скопіювати з Render Dashboard і за потреби додати до README та цього звіту.

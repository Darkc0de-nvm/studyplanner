# Доступність StudyPlanner

Документ фіксує перевірки WCAG 2.2 AA для клієнта StudyPlanner у Фазі 3: автоматичний аудит axe-core, keyboard-only проходи та ручні перевірки. Аудит виконується в Chromium; Firefox використовується для поведінкових e2e-тестів.

## 1. Підсумок

| Перевірка | Обсяг | Результат |
|---|---|---|
| axe-core (WCAG 2.0/2.1/2.2 A+AA) | 30 сторінок/станів × 2 ширини = **60 тестів** | **0 serious/critical**, усі 60 пройшли |
| Keyboard-only | вхід, додавання, редагування, видалення, діалоги, меню користувача, календар, skip-link, 200 % zoom | **8/8** тестів пройшли |
| Горизонтальний скрол на 720 px (проксі 200 % zoom) | `tasks.html` | немає (`scrollWidth - innerWidth ≤ 1`) |
| Контраст бейджів і тексту помилок | усі дисципліни, `.alert--error`, `.tag` | виправлено, axe-порушень немає |
| Reduced motion | `prefers-reduced-motion: reduce` | анімації вимкнено базовим CSS |

Команди:

```powershell
cd server
npx playwright test e2e/specs/a11y.spec.js --project=chromium
npx playwright test e2e/specs/keyboard.spec.js --project=chromium
```

## 2. Що саме перевіряє axe

Теги: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`. Для кожної сторінки/стану перевіряються лише `serious` і `critical`; будь-яке таке порушення валить тест із переліком селекторів і HTML-фрагментів.

Сторінки (7): `tasks`, `calendar`, `login`, `register`, `index`, `privacy`, `terms`.

Додаткові сторінки (4): `404`, `500`, `offline`, `states`.

Стани (19): пошук, «нічого не знайдено», перший запуск, фільтр і відкритий фільтр, виконані, меню користувача, порожні деталі, діалоги додавання/редагування/деталей/видалення, datepicker, помилки форми завдання, помилки входу й реєстрації, фільтр календаря та відкритий фільтр, порожній день календаря.

Ширини: **1440 px** (desktop) і **390 px** (mobile). Перед аудитом фіксується годинник (`2026-10-06`) і виконується вхід у демо-акаунт, щоб приватні сторінки були в однаковому стані.

## 3. Виправлені порушення

| Проблема | Рішення | Файли |
|---|---|---|
| Недостатній контраст заповнених бейджів дисциплін | Додано окремі `--discipline-*-fill` (`#1D4ED8`, `#6D28D9`, `#047857`) і білий текст `--primary-foreground` для `.task-card .tag`, `.task-details .tag` | `client/css/tokens.css`, `client/css/pages/app.css` |
| Недостатній контраст тексту помилок | Темніший `--destructive-strong: #B91C1C` для `.alert--error` | `client/css/tokens.css`, `client/css/components.css` |
| `label-content-name-mismatch` у клітинках календаря | Видимий текст (дата + назви завдань) залишено на початку доступного імені; повна дата й кількість завдань додані як `.visually-hidden`-опис, а не через `aria-label` | `client/js/calendar.js` |
| Кнопка меню користувача без доступного імені | Замість `aria-label` на `<summary>` додано видимий для скрінрідера текст «Меню користувача» | `client/tasks.html`, `client/calendar.html`, `client/states.html` |
| Іконкові кнопки без назв | Усі інтерактивні іконки мають текстову назву або `.visually-hidden`-підпис | `client/*.html` |

Після виправлень візуальна база оновлена лише там, де зміни були навмисні (контраст бейджів і тексту помилок); повторний прогін `visual.spec.js` — **118/118** у Chromium і Firefox.

## 4. Ручні перевірки

### 4.1. Keyboard-only

Автоматизовано в `server/e2e/specs/keyboard.spec.js`:

1. Skip-link — перший Tab, Enter веде до `#main`.
2. Вхід повністю з клавіатури: email → пароль → submit → `/tasks.html`.
3. Діалог додавання відкривається з `.app-add`, фокус переходить у поле назви; Escape закриває діалог і повертає фокус на кнопку.
4. Меню користувача (`<details>`) відкривається Enter-ом.
5. Клітинка календаря відкриває день із клавіатури.
6. Редагування завдання: Tab до `[data-action="edit"]` → Enter → фокус у `#edit-task-name` з поточним текстом → заміна назви з клавіатури → Enter зберігає, картка оновлюється, діалог закривається.
7. Видалення завдання: Tab до `[data-action="delete"]` → Enter → фокус у `#task-delete` → Tab до `[data-confirm-delete]` → Enter видаляє картку й закриває `alertdialog`.
8. Ширина 720 px не дає горизонтального скролу (проксі 200 % zoom).

### 4.2. Фокус і порядок

- Глобальний `:focus-visible` з контрастним outline; для календарних клітинок і полів — окремі стани.
- Діалоги керують фокусом: відкриття → перше поле, закриття → джерело відкриття.
- `aria-live="polite"` використовується для статусу збереження та повідомлень про помилки/успіх.
- Приховані описи не потрапляють у Tab-порядок (`.visually-hidden`, не `display:none`).

### 4.3. Контраст

Перевірено axe-правилом `color-contrast` на всіх сторінках і станах. Додатково вручну перевірено бейджі трьох дисциплін на картках і в деталях, текст `.alert--error`, посилання та підписи полів. Проблемних пар «текст/фон» не залишилось.

### 4.4. Reduced motion і zoom

- `@media (prefers-reduced-motion: reduce)` вимикає переходи й анімації; перевірено в DevTools і CSS-оглядом.
- 200 % zoom моделюється шириною 720 px: горизонтального скролу немає, контент переходить в одну колонку.

## 5. Відомі обмеження

1. **axe — не повна перевірка.** Автоматика не оцінює змістовність alt-текстів, логіку порядку читання та якість повідомлень; ці пункти перевірені вручну й задокументовані вище.
2. **Скрінрідер не тестувався живим NVDA/VoiceOver.** Доступні імена, ролі та `aria-live` перевірені через DOM/axe і keyboard-тести; окремий прохід з екранним диктором — рекомендація для наступної ітерації.
3. **Аудит лише в Chromium.** Firefox покриває поведінкові e2e-сценарії, але не axe; розбіжності рендерингу Firefox можуть дати інші результати контрасту.
4. **Користувацькі дані.** Довгі назви дисциплін/завдань можуть переноситися на кілька рядків; це перевірено візуально, але не є окремим a11y-тестом.
5. **<details>-меню.** Нативний елемент дає коректну семантику й клавіатуру, але не має повного `role="menu"`-патерну зі стрілками; для трьох пунктів це прийнятний компроміс.

- `server/e2e/specs/a11y.spec.js` — 60 axe-тестів.
- `server/e2e/specs/keyboard.spec.js` — 8 keyboard-only тестів (включно з редагуванням і видаленням завдання).
- `server/e2e/specs/visual.spec.js` — 118 візуальних еталонів (регресія після a11y-фіксів).
- `client/css/utilities.css` — `.visually-hidden`.
- `client/css/base.css` — `:focus-visible`, `prefers-reduced-motion`.
